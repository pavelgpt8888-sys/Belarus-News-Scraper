# Belarus News Scraper

Учебный Python-парсер заголовков новостей белорусского портала [Onlíner](https://www.onliner.by/).
Раз в день он собирает свежие публикации из трёх разделов и сохраняет их в CSV-таблицу,
которая открывается в Excel.

[Кейс для портфолио: архитектура, надёжность, демонстрация и проверяемые результаты](PORTFOLIO_CASE.md).

> **Это учебная демонстрация.** Проект сохраняет только заголовки, метаданные и ссылки
> на оригинальные публикации. Полные тексты, изображения и комментарии не копируются:
> чтобы прочитать новость, переходите по ссылке на сайт Onlíner. Все права на материалы
> принадлежат их правообладателям.

## Готовый результат

Свежий файл всегда лежит в репозитории: **[data/news.csv](data/news.csv)**.
На GitHub его можно посмотреть в виде таблицы или скачать кнопкой «Download raw file».

## Какие новости собираются

| Категория | Источник |
|---|---|
| Технологии | https://tech.onliner.by/ |
| Экономика и деньги | https://money.onliner.by/ |
| Общество | https://people.onliner.by/ |

За один запуск сохраняется не больше **30 публикаций из каждой категории**, то есть до 90 строк.

Колонки CSV:

| Колонка | Что содержит |
|---|---|
| `category` | категория: Технологии / Экономика и деньги / Общество |
| `source` | источник, например `Onlíner (tech.onliner.by)` |
| `title` | заголовок публикации |
| `url` | прямая ссылка на статью без меток и параметров |
| `published_at` | дата и время публикации по Минску, например `2026-10-12T17:50+03:00`; если точного времени на странице нет — только дата из ссылки |
| `collected_at` | дата и время сбора данных по Минску |

Файл сохраняется в кодировке **UTF-8 с BOM**, поэтому Excel показывает русский текст без «кракозябр».

## Как работает программа

1. `scraper.py` по очереди скачивает главную страницу каждого раздела обычным GET-запросом
   (`requests`) с понятным User-Agent и паузами между запросами.
2. Из HTML (`BeautifulSoup`) извлекаются только карточки новостей раздела:
   - лента `news-tidings` — заголовок, ссылка и точное время публикации;
   - крупные плитки `news-tiles` — подборка редакции, используется как запас, если свежих
     новостей меньше 30.

   Меню портала, рекламные блоки, ссылки на комментарии и статьи других разделов отбрасываются.
3. Если на первой странице меньше 30 новостей, программа догружает следующие так же,
   как кнопка «Загрузить ещё» на сайте (не больше двух дополнительных запросов).
4. Ссылки приводятся к единому виду (`https://`, без `?utm…`, `#…` и завершающего `/`),
   дубликаты удаляются.
5. Результат записывается в `data/news.csv` через временный файл, поэтому при сбое старый CSV
   не повреждается.

### Обработка ошибок

- Если раздел недоступен, вернул ошибку HTTP или страницу без новостей, выводится понятное
  сообщение, а остальные разделы обрабатываются как обычно. Для неработающего раздела
  в CSV остаются данные прошлого успешного запуска.
- Если не сработал ни один раздел, программа завершается с кодом `1` и **не трогает**
  существующий `data/news.csv`. Вымышленные данные никогда не создаются.
- При ответах 403/429 или странице проверки (CAPTCHA) парсер не пытается обойти защиту,
  а просто останавливает сбор с этого раздела.

### Правила доступа

`robots.txt` разделов Onlíner разрешает индексацию главных страниц разделов и статей.
Парсер делает около 9 запросов в день (по 3 на раздел), не загружает сами статьи
и не обходит ограничения доступа.

## Запуск вручную

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/pavelgpt8888-sys/Belarus-News-Scraper.git
cd Belarus-News-Scraper

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python scraper.py
```

Пример вывода:

```text
[tech] https://tech.onliner.by/
  собрано новостей: 30
[money] https://money.onliner.by/
  собрано новостей: 30
[people] https://people.onliner.by/
  собрано новостей: 30
Сохранено 90 строк в data/news.csv
```

Офлайн-тесты (без обращения к сайту):

```bash
python -m unittest discover -s tests -v
```

## Автоматическое обновление (GitHub Actions)

Workflow [`.github/workflows/scrape.yml`](.github/workflows/scrape.yml):

- запускается **каждый день примерно в 09:17 по Минску** (`cron: 17 6 * * *` в UTC);
  GitHub при высокой нагрузке может запускать расписание с задержкой;
- устанавливает зависимости, прогоняет тесты и запускает `scraper.py`;
- если `data/news.csv` изменился, коммитит его от имени `github-actions[bot]`;
  если изменений нет — коммит не создаётся;
- использует встроенный `GITHUB_TOKEN` только с разрешением `contents: write`.
  Личные токены и секреты не нужны.

**Ручной запуск:** вкладка **Actions** → **Update news** → **Run workflow** → **Run workflow**.

Если коммит завершается ошибкой `Permission denied` / `403`, разрешите запись для workflow:
**Settings → Actions → General → Workflow permissions → Read and write permissions → Save**.

> GitHub автоматически отключает расписание в публичных репозиториях, если в них
> 60 дней не было активности. Тогда включите workflow снова на вкладке Actions.

## Ограничения

- Вёрстка Onlíner может измениться. Тогда парсер честно сообщит, что новости не найдены,
  и селекторы в `parse_cards()` нужно будет обновить.
- В проекте намеренно нет интерфейса, базы данных, бота и AI-анализа: это минимальный
  учебный пример.
